# 메모리 시작 세트

여러 프로젝트에서 되풀이된 원칙과 함정이다. 이 저장소에 맞는 항목만 골라 메모리 색인으로 옮긴다. 옮긴 뒤 규칙으로 굳은 항목은 `AGENTS.md` 로 옮기고 여기서 지운다.

## 원칙

- 근본 원인을 고친다 — 임시로 우회한 수정은 같은 문제를 다른 자리에서 다시 만든다.
- 「구현했다」와 「머지했다 · 서버에 반영했다」를 구분해 보고한다 — 완료는 머지 · 재기동 · 확인까지다.
- 머지하지 않은 브랜치는 정리할 때도 지우지 않는다 — 지우기 전에 사용자에게 묻는다.
- 폴더를 지우기 전에 심볼릭 링크와 워크트리가 그 폴더를 가리키는지 확인한다.
- 레인(서브에이전트)의 워크트리는 띄우기 직전의 기준 브랜치에서 만든다 — 오래된 기준은 틀린 보고를 낳는다.
- 절차에 없는 단계를 더하려면 먼저 묻는다.

## 함정

- 같은 워크트리에서 테스트 실행기 두 개를 동시에 돌리면 산출물 폴더가 겹쳐 가짜 실패가 난다 — 순서대로 돌린다.
- 지운 워크트리에서 뜬 빌드 · 감시 프로세스가 남아 CPU 를 쓰면 테스트가 시간 초과로 실패한다 — 실패를 믿기 전에 부하를 먼저 본다.
- 개발 서버가 고치기 전 코드를 내보낼 수 있다 — 화면을 확인하기 전에 응답에 새 코드의 표식이 있는지 본다.
- 개발 서버의 포트가 다른 워크트리의 서버일 수 있다 — 확인하기 전에 그 포트의 프로세스가 어느 폴더에서 떴는지 본다.
- 검증하는 동안 그 워크트리에 커밋하면 빌드가 바뀌어 검증 결과가 낡는다 — 검증이 끝난 뒤 커밋한다.
- 통합 테스트가 개발 DB 를 쓰면 데이터가 섞인다 — 테스트 전용 DB 를 따로 띄운다.
- 테스트가 비정상으로 끝나면 DB 세션이 남아 다음 실행이 멈춘다 — 다시 돌리기 전에 남은 세션을 끊는다.
- 큰 파일(100 MB 이상)이 든 커밋은 호스팅이 push 를 거절한다 — 산출물은 커밋 전에 크기를 본다.
- 한글이 많은 소스를 `grep` 이 바이너리로 잘못 판단해 결과를 빠뜨린다 — `rg -a` 를 쓴다.
- 임시 폴더는 재부팅하면 비워진다 — 다시 볼 보고와 산출물은 저장소나 지속되는 폴더에 둔다.
- 긴 게이트가 도는 동안 머신이 잠들면 시간 초과로 실패한다 — 잠들지 않게 하고 동시에 도는 작업을 줄인다.
