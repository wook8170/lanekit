# {{project}} 작업 지침

이 파일이 에이전트와 사람이 함께 따르는 정본 지침이다. 규칙은 여기 한 곳에만 둔다.

## 시작 문서

- 세션을 시작하면 `progress.md` 를 먼저 읽고, 앞 세션이 어디까지 했는지 확인한다.
- 결정의 배경이 필요하면 `docs/decisions/` 에서 찾는다.
- 메모리에 무엇을 넣는지는 `docs/memory-guide.md` 를 따른다.

## 저장소 모양

| 폴더 | 내용 |
|---|---|
| `scripts/lanekit/` | 게이트 실행기와 검사다. lanekit 이 복사한 파일이라 직접 고치지 않는다. 프로젝트의 사정은 `lanekit.config.json` 에 적는다 |
| `docs/decisions/` | 결정 기록이다. 결정 하나에 파일 하나를 둔다 |
| `.lanekit/` | 레인 보고 · 게이트 증거 파일이다. git 이 추적하지 않는다 |

프로젝트의 폴더를 이 표에 더한다. 폴더마다 「무엇을 하는 곳인가 · 먼저 읽을 파일」을 한 줄로 적는다.

## 코드 작성 기준

- 크기 상한: 파일 500줄, 함수 60줄(넘으면 경고, 100줄이면 실패), 복잡도 15, 중첩 4. 이미 넘은 파일과 함수는 더 키우지 않는다. 새 파일과 새 함수는 처음부터 상한 안에 둔다.
- 판정과 실행을 나눈다. 「해도 되는가 · 무엇을 할까」는 입력을 받아 결과를 돌려주는 순수 함수로 두고, 실제로 바꾸는 코드와 섞지 않는다.
- 기능 단위로 나눈다. 함수를 위치 순서대로 잘라 `part2` · `helpers2` 같은 조각을 만들지 않는다.
- 매개변수와 입력 객체의 칸은 7개 이하로 둔다. 화면 컴포넌트의 props 는 12개 이하로 둔다.
- 한 글자 이름과 약어 이름(`tmp` · `cfg` · `obj` · `val`)을 쓰지 않는다. 불리언은 `is` · `has` · `can` · `should` 로 시작한다.
- 주석에는 무엇과 왜를 쓴다. 버전 번호 · 티켓 번호 같은 이력은 git 기록에 둔다.
- 새 파일의 첫머리에 주석 3줄을 둔다: 맡는 일 · 부르는 곳 · 먼저 읽을 파일.
- 오류를 빈 `catch` 로 넘기지 않는다. 무시해도 되는 오류도 이유와 함께 기록한다.
- 같은 규칙은 한 곳에 둔다. 코드를 옮긴 뒤 옛 경로에 다시 내보내기 파일을 남기지 않는다.

## 탐색 순서

1. 코드의 흐름 · 위치 · 변경의 영향은 codegraph 로 먼저 찾는다.
2. 문서 · 설계 · 결정 이력은 문서 위키로 먼저 찾는다. 명령은 `.lanekeeper/config.json` 의 `docs_search.search` 에 있다.
3. 정확한 줄과 문자열은 `rg` 로 확인한다. 색인이 없는 파일(설정 · 생성물)도 `rg` 로 찾는다.

## 완료 기준

- 변경에 맞는 테스트와 문서를 같은 변경에서 고쳤다.
- `node scripts/lanekit/gate.mjs --profile light` 가 통과한다.
- 「구현했다」와 「머지했다 · 배포했다」를 구분해서 보고한다.
- 웨이브를 마치면 `progress.md` 를 고친다.

## 테스트 동기화

기능을 더하거나 고치거나 지울 때마다 같은 변경에서 테스트를 맞춘다.

| 변경 | 테스트 |
|---|---|
| 추가 | 새 동작 · 경계값 · 오류 경로의 테스트를 더한다 |
| 수정 | 기대값을 고치고, 고치기 전 코드에서 실패하는 회귀 테스트를 더한다 |
| 삭제 | 지운 기능의 테스트를 지운다. 함께 쓰는 동작의 테스트는 남긴다 |

결함을 찾았는데 지금 고칠 수 없으면 테스트를 약하게 바꾸지 않는다. 보류 표시와 결함 기록으로 남긴다.

## 문서 크로스체크

기능을 바꾸면 그 기능을 설명하는 문서를 같은 변경에서 고친다. 숫자와 목록은 기존 문서에서 옮겨 적지 않고 세어서 쓴다. 확인하지 못한 것은 추측으로 채우지 않고 「미확인」으로 남긴다. 문서의 숫자와 코드에서 센 값을 `lanekit.config.json` 의 `checks.docs-drift.facts` 에 적어 두면 게이트가 차이를 찾는다.

## 게이트

```
node scripts/lanekit/gate.mjs --profile light     # 웨이브마다, push 전
node scripts/lanekit/gate.mjs --profile changed   # PR
node scripts/lanekit/gate.mjs --profile full      # 출하 전
```

- 검사마다 `mode` 가 있다: `off` · `warn` · `ratchet` · `fail`. 처음에는 `warn` 으로 두고, 기준선을 잠근 뒤 `ratchet` 으로 올린다.
- 기준선을 다시 잠그려면 사유가 있어야 한다. 값이 늘어나는 재잠금은 `docs/decisions/` 의 결정 파일이 있어야 한다.
- 게이트를 돌릴 때마다 `.lanekit/evidence/` 에 증거 파일이 남는다. 출하에는 깨끗한 작업 트리에서 돌린 full 증거를 쓴다.

## Git

- 긴 수명의 브랜치는 `main` 하나다. 작업은 브랜치에서 하고 PR 로 합친다.
- 병렬 레인은 레인마다 워크트리와 브랜치를 따로 쓴다. 레인은 자기 브랜치에 커밋한다. 통합 브랜치와 `main` 에 합치는 일은 메인 세션이 한다.
- 커밋과 push 는 사용자가 지시할 때 한다. 머지하지 않은 브랜치는 정리할 때도 지우지 않는다.
- 끝난 워크트리는 합친 뒤 지운다. 지우기 전에 그 경로에서 뜬 프로세스를 끝낸다.
