# 출하 점검표

버전을 낼 때마다 위에서부터 차례로 한다. 건너뛴 칸이 있으면 이유를 릴리스 노트에 적는다.

## 1. full 게이트

- [ ] 작업 트리가 깨끗하다(`git status` 에 바뀐 파일이 없다)
- [ ] `node scripts/lanekit/gate.mjs --profile full` 이 통과한다
- [ ] `--skip` 으로 건너뛴 검사가 없다

## 2. 증거 확인

- [ ] `.lanekit/evidence/<커밋>-full.json` 의 `dirty` 가 `false` 다
- [ ] 같은 커밋의 출처 문서(`<커밋>-provenance.json`)와 SBOM 이 있다
- [ ] 의존성 감사에서 받아들인 항목의 만료일이 지나지 않았다

## 3. 태그

- [ ] 버전 파일과 변경 이력을 올렸다
- [ ] 증거 파일의 커밋에 태그를 붙였다

## 4. 릴리스 노트

- [ ] 사용자가 보는 변경을 적었다
- [ ] 알려진 문제와 건너뛴 검증을 적었다

## 5. 업그레이드 안내

- [ ] 설정 · 데이터 형식이 바뀌었으면 옮기는 순서를 적었다
- [ ] 되돌리는 방법을 적었다

이 게이트가 만드는 출처 문서는 서명이 없는 문서(SLSA Build L1 수준)다. 서명과 호스팅 빌드가 필요하면 프로젝트가 따로 마련한다.
