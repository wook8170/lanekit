# 레인 공통 지시

레인을 띄울 때 이 파일을 지시문 앞에 붙인다. 괄호로 표시한 칸만 버전과 웨이브에 맞게 채운다.

## 이번 웨이브

- 버전과 웨이브: (채운다)
- 통합 브랜치와 기준 커밋: (채운다)
- 이 레인이 고치는 파일의 범위: (채운다)
- 건드리지 않는 파일: (채운다)

## 말과 글

- 보고는 사용자의 언어로 쓴다. 코드 · 경로 · 명령은 원문 그대로 둔다.
- 문장 사이의 관계(이유 · 결과 · 대조 · 조건)를 연결하는 말로 드러낸다.
- 사물을 사람처럼 쓰지 않고, 실제로 일어나는 일을 쓴다.
- 명사를 셋 이상 조사 없이 잇지 않는다.
- 주어와 서술어 사이를 길게 벌리지 않는다.
- 업계에서 통용되는 용어(버전 · 브랜치 · 커밋 · 테스트 · 빌드)는 번역하지 않는다.

## 지킬 것

- 자기 워크트리와 자기 브랜치에서만 일한다. 범위 밖의 파일을 고쳐야 하면 고치지 않고 보고에 적는다.
- 한 파일은 한 레인만 고친다.
- `AGENTS.md` 의 「코드 작성 기준」을 지킨다. 새 파일과 새 함수는 처음부터 상한 안에 둔다.
- 게이트의 기준선(`scripts/lanekit/baselines/`)은 고치지 않는다. 기준선은 메인 세션만 잠근다.
- `git stash` 를 쓰지 않는다. 머지하지 않은 브랜치를 지우지 않는다.
- 브라우저는 헤드리스로만 띄운다.
- 운영 데이터와 사용자가 쓰는 개발 DB 에 쓰지 않는다. 테스트는 테스트용 DB 로 돌린다.

## 테스트와 부하

- 자기가 만들거나 고친 테스트 파일만 실행한다. 전체 테스트와 full 게이트는 메인 세션이 레인의 결과를 합친 뒤 한 번 돌린다.
- 테스트와 빌드 전에 부하를 확인한다. 부하가 높으면 내려갈 때까지 무거운 단계를 기다린다.
- 같은 워크트리에서 테스트 실행기 두 개를 동시에 돌리지 않는다.
- 기능을 바꾸면 같은 변경에서 테스트를 맞춘다. 해당이 없으면 테스트를 열어 보고 확인했다고 적는다.

## 탐색

- 코드는 codegraph 로 먼저 찾고, 문서와 결정은 문서 위키로 먼저 찾는다. 정확한 줄은 `rg` 로 확인한다.

## 보고

보고는 반환과 함께 `.lanekit/reports/<레인>.md` 파일로도 남긴다. 다음을 적는다.

- 바꾼 파일
- 실행한 테스트 명령과 결과
- 돌리지 않은 검증과 그 이유
- 문서를 고친 곳, 또는 해당 없음을 확인한 근거
- 결함 후보와 남은 일
